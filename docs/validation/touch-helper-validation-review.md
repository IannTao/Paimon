# 工单 01 后续验证与状态修复审查

日期：2026-10-29。比较基点：`1258dc0`，审查 `git diff HEAD` 的后续工作区变更及新增回放测试、采样脚本。规格来源：`input-coexistence-research.md`、`touch-helper.md`、工单 01。按 code-review 技能由独立 Standards / Spec 两轴复审。

## Standards

确定代码问题或规范违规：0 项。无合成时完整键/槽不一致帧原样转发；合成已活动时先按旧真实状态结束合成，再转发源帧；不改写真实 tracking ID。不一致期间拒绝新合成，真正同步丢失、非法槽/ID、重复 ID 仍有健康检查。正常交接核查实时槽、键和内核队列。只读采样脚本按所属子进程清理。

验证缺口：需要修复版真机证据确认真实 pointerId 没有 CANCEL、意外 UP 或重新 DOWN；离线回放不能替代该证据。

## Spec

新增阻塞：0 项。修复符合状态不完整时停止新增合成、真实流保留转发的要求；恢复键/槽一致后才重新允许合成。正常交接不会因 MT 槽为空而忽略仍按下的 BTN_TOUCH。

验证边界：仅修复代理把完整 key-only 帧当作丢失状态而退出的条件，不等于证明该源帧在 MyOS 下的手势连续性。修复版真机复测、真实双指加合成第三触点以及游戏验收仍须以设备报告为准，见 [实测记录](touch-helper-device-validation.md)。

两轴确定问题均为 0；两轴均要求补修复版真机连续性证据，不能据此解除工单门槛。

## 收尾缓解复审

比较基点为 `d29dba4`。Standards 和 Spec 均未发现100ms源空闲观察逻辑的确定阻塞/错误释放问题：等待期间继续读写和心跳，完整源帧或实时空闲检查失败重置窗口，最终仍检查live槽、键和队列，create/grab不增加等待，硬期限不延长。它是候选时序缓解，不是InputReader消费确认；持续源帧可能导致硬期限强制恢复。

Spec独立检查失败对照 `merge-moving-trace-1793281715506.jsonl` 的3413个事件/6447条history：原两指在合成后继续移动约12秒，最后一指CANCEL，没有最终UP，其余结构无异常。新增断言脚本可以捕捉这个CANCEL回归，但不隔离deviceId、不核对原指针集合，不能单独用作完整连续性通过结论。

首轮缓解后 `merge-settled-1793281959138.jsonl` 的3678个事件/6887条history经Spec独立全量检查，动作、指针集合、downTime和时序均无异常；0CANCEL、正常最终UP。合成窗实际61ms（122931965–122932026），其中6个MOVE、8条history，原两指坐标有轻微变化；不能称为持续大幅移动。源UP到销毁间隔102ms，支持该轮缓解有效，仍需无诊断日志的重复及停止期间重新落指等后续检查，不解除游戏门槛。

正式版两轮也已只读全量复核：4036事件/7478history和7208事件/13804history，各一次57ms第三触点，均0CANCEL、原指针连续、最终UP；另有309事件/522history的无合成前段正常结束。动作转换、指针集合、downTime与时序均无异常。第二正式轮合成窗仅原pointer1发生坐标变化，不把结果扩大为每轮双指都同时移动。可归档为阶段内3次单点击成功（一诊断、两正式），不替代游戏10次重复及异常恢复门槛。用户随后停止01真机测试、转入02开发。
