# 全自动跑图采集设计

2026-10-29，用户确认首版覆盖自动跑图到资源点、调整视角并拾取，玩家在任务执行期间不手工介入。本文保留原路径以兼容已有引用，替代原“玩家手动游玩时自动拾取”方案。架构变更见 [ADR 0003](adr/0003-autonomous-gathering.md)，领域术语见 [术语表](../GLOSSARY.md)。

全自动范围已经确认；下述闭环和实施顺序为据此调整的设计，具体路线、参数及验收阈值仍需细化。本文不表示功能已经实现或真机验证已经通过。

## 运行边界

- 与原神在同一台实体 Android 手机上独立运行，日常执行不依赖电脑、另一台设备或网络。
- Rust 实现核心，Kotlin 接入 Android 平台能力；沿用无障碍服务与 Shizuku 权限方向，输入路径需重新验证，不预设必须使用触控代理 helper。
- 只读取屏幕画面并使用 Android 系统输入，不读取或修改游戏内存，不修改游戏文件。
- 验证设备仍为 nubia Z50 Ultra、Android 14、MyOS 14.5.33，原神界面为中文；首版固定游戏显示设置与横屏方向，实际配置随验证记录。
- 先交付自用验证 APK，保留必要的权限引导、任务启停和诊断能力。

## 首版范围

- 自动移动到资源点、调整视角、识别拾取提示、执行拾取并确认结果，连续推进采集任务。
- 运行中不依赖玩家按摇杆、转视角、点击拾取、标记当前位置或手工脱困。
- 自动拾取作为采集任务的一环，不再单独以“玩家手动跑图、程序补点”为首版产品形态。
- 只拾取明确出现直接拾取提示的物品，未知提示不猜测；对话、开启宝箱、调查、通过攻击采矿和自动战斗不纳入首版。
- 首版优先选择不要求上述额外交互的采集路线；具体路线与起点条件尚待确定。无法处理的障碍应自动恢复或明确结束任务，不交给玩家继续完成。
- 暂不要求兼容 BetterGI 的脚本、路线与配置格式，不提供物品黑白名单。

## 执行闭环

1. **准备检查**：检查权限、画面获取、前台游戏、屏幕配置和任务起点条件。不满足时不发出游戏操作，并报告原因。
2. **定位与进度判断**：从屏幕确认当前位置或可用的导航参照，判断与当前资源点的关系。不能用预定输入已执行来代替实际到达证据。
3. **自动移动**：程序控制摇杆与所需视角操作，观察移动效果，修正方向；控制按住与释放的生命周期，不盲目按固定时长无限前进。
4. **到点与对准**：依据画面确认接近资源点，调整位置和视角，寻找可直接拾取的提示。
5. **拾取与确认**：只点击明确的拾取提示，观察后续画面确认结果。输入命令成功不等于取得物品，也不单凭提示消失断言拾取成功。
6. **推进或结束**：处理当前资源点后继续下一资源点；全部完成或遇到不能恢复的问题时释放全部输入，结束并记录结果。

具体定位方法、路线表达、到点判据和拾取成功证据在闭环原型中确定。纯坐标、固定时长动作可用于能力探测，不能独立作为完整采集方案。

## 输入与画面方案

程序统一协调移动、视角和拾取，平台层必须能可靠表达需要的按住、移动、点击和释放。是否需要同时维护多个合成触点由实际游戏操作验证决定；取消真实手指共存要求不代表单次 input tap 已足够完成导航。

旧触控共存实验及 helper 保留为历史资料和候选能力，不再是首版推进前置条件。新的首个技术门槛是：在基准设备上，无玩家触控地完成一次“观察画面 → 移动到资源点 → 调整视角 → 拾取 → 确认结果”的闭环，并在异常或结束时可靠释放输入。

07 自动移动验证已采用 shell Shizuku 原始截图流，只在内存处理，并取得固定设备上的移动反馈证据，见 [验证记录](validation/ticket-07.md)。该路径不需要 MediaProjection 授权；完整采集所需的识别覆盖和性能仍待后续验证。若后续改用 MediaProjection，仍需在执行前完成系统要求的授权，会话中断后结束当前任务，不把人工补授权作为自动恢复步骤。

## 启停与异常处理

- 安装、系统授权和选择任务属于运行准备；准备完成并启动后，任务自行推进，不要求逐点确认。程序启动默认空闲，保留主动停止入口。
- 对短暂画面不确定、未找到资源、移动无进展等情况采用有次数或时间上限的重新观察、视角调整或重新定位；具体策略与上限待原型确定。
- 无法确认位置或进度时停止盲目前进；超过恢复上限后释放输入并记录失败原因，不能反复尝试到无限运行。
- 权限失效、截图会话结束、离开游戏或锁屏时停止任务并释放可控输入。重新启动为新一次任务，不把中断后的人工处理计为原任务自动完成。
- 玩家可以随时主动停止，但正常成功路径与异常恢复不以玩家接管为步骤。
- 默认不保存截图，仅主动启用诊断时保存必要画面；记录资源点进度、恢复次数、停止原因和任务结果。

## 实施顺序

1. 确定一条短路线及可复现的起点条件，避开战斗和非直接拾取交互。
2. 验证画面获取及程序控制移动、视角、拾取和释放输入的基础能力。
3. 实现到单个资源点并拾取的屏幕反馈闭环，验证全程无玩家游戏操作。
4. 扩展为连续资源点任务，加入进度判断、有界恢复、停止与诊断。
5. 在固定设置下重复完整任务，记录成功率、完成时长、误操作、帧率、温度和功耗。

## 验收方向

- 成功任务必须从约定起点自动推进到任务结束，全程玩家游戏操作为 0 次；需要玩家补操作的任务计为失败。
- 必须观察到实际移动、到点、视角调整和取得物品，不能只检查输入命令返回码。
- 误点对话、宝箱、调查等范围外交互的目标为 0 次；未知提示应跳过并按恢复策略处理。
- 验证移动无进展、位置不确定、资源缺失、截图中断、权限失效、切离游戏以及主动停止时的行为；恢复必须有界，停止必须释放输入。
- 人工可在执行后复核证据，不参与运行中的导航或决策。
- 原方案的 30 分钟运行、100 次拾取机会、95% 拾取率、1 秒响应和帧率下降不超过 10% 是手动游玩场景下的旧验收目标，不直接视为完整采集任务的新承诺。新任务的重复次数、成功率、时间及性能阈值待短路线确定后设定，未测量项明确标记为未验证。

## 待细化

首条路线、可接受的起点条件、导航参照、资源缺失时的任务判定、恢复上限和数值验收标准尚未确定。不据本次范围调整推定支持任意地点启动、任意地图路径规划、战斗或传送。
