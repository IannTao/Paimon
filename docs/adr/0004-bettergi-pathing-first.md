# 先兼容 BetterGI 路径点，再实现路线驱动的跑图采集

2026-10-30，用户明确要求优先兼容 bettergi-scripts-list 的 repo/pathing 路径点，再据此实现跑图和拾取。此决定取代原设计和规格中“首版不要求兼容 BetterGI 路线格式”的排除项，并调整 ADR 0003 下的实施顺序：先导入、校验和预览路线，再验证游戏坐标定位、按路径点导航与自动传送，最后接入到点拾取和完整采集任务。

路线原文件及有序路径点是后续执行的依据，不要求用户重新录制 Paimon 专用坐标序列；手机端通过屏幕观察定位并映射到相同游戏坐标系，Android 输入由本项目实现。能够读取文件与能够完整执行路线分别判定，不把未知点类型、移动模式或动作静默丢弃后声称兼容；需要的传送纳入基础路线执行，飞行、角色技能和战斗等能力按支持矩阵逐步扩展。

ADR 0002 的交互边界及 ADR 0003 的同机独立、执行期间无人操作、异常有界恢复或结束要求继续有效。已完成的 07 保留为底层输入与相对位移证据，不能证明已具备 BetterGI 游戏坐标定位或路线兼容能力。
