# 07: 从应用启动并完成一次有画面反馈的自动移动

**What to build:** 完成授权后从应用启动一次短距离移动验证，程序检查游戏画面，自动按住并释放摇杆，通过后续画面确认移动效果，结束并显示结果；作为采集任务的最小贯通路径，不宣称完整采集通过。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Lifecycle:** closed

**Source:** [Android 全自动跑图采集规格](../../../docs/specs/android-auto-pickup.md)。

同机独立运行，Rust 核心与 Kotlin 平台接入；仅通过屏幕观察与 Android 系统输入操作游戏，不读写游戏内存或修改游戏文件，不预设 Root 或日常外部设备控制。执行期间不依赖玩家游戏操作，遵循 ADR 0003 的全自动采集方向，不依赖旧真实触控共存门槛。测试以完整采集任务入口的外部行为为主，替身与回放不能替代真机游戏证据。

- [x] 记录可复现短路线的候选起点、首个资源点、固定显示设置与导航参照，避开战斗及范围外交互；不要求本票具备完整导航。
- [x] 可安装 APK 贯通权限与画面获取引导、默认空闲、明确启动、Rust 决策、真实输入和结果展示；不将旧触控共存通过作为前提。
- [x] 前台、授权、画面和屏幕配置检查失败时不执行移动；使用屏幕反馈验证移动效果，不以输入命令成功判定。
- [x] 移动有时限；完成、主动停止、输入失败、画面中断、切离游戏和锁屏均停止并释放可控输入，迟到结果不会恢复任务。
- [x] 提供任务入口行为测试和基准真机结果，运行中无人游戏操作；不能实测时明确未验证。
- [x] 默认不持久保存截图，不依赖日常网络；代码整理只服务于本票贯通，不破坏已有可用构建。
