# 17: 按导入路线的地面路径点自动跑图

<!-- paimon-github-archive -->
> 2026-10-31 已迁移到 [GitHub #18](https://github.com/IannTao/Paimon/issues/18)。本地编号 17 仅作追溯；以下为迁移前快照，当前状态、依赖及讨论以 GitHub 为准。

**What to build:** 在已确认起点条件下，程序使用导入路线中的 walk 与 path/target/orientation 点，自动移动、修正朝向和有序推进，并在结束或异常时释放输入。

**Blocked by:** [16: 将手机屏幕定位对应到 BetterGI 游戏坐标](16-bettergi-game-coordinate-localization.md)，且基础场景坐标定位须有真机通过证据。

**Status:** ready-for-agent

**Lifecycle:** open

**Source:** [全自动跑图采集规格](../../../docs/specs/android-auto-pickup.md)、[路径点兼容方案](../../../docs/bettergi-pathing-compatibility.md)。

遵循 ADR 0002、0003、0004：同机独立、本地处理、屏幕观察加系统输入，执行期间无人游戏操作。导入、定位和执行的通过证据分别记录，不以旧触控共存门槛阻塞，也不以 07 已通过替代本票能力验证。

- [ ] 从同一导入原文件构造任务，保持坐标与点序；明确途经、精确经过和只朝向的不同判据，不把 target 一律当成物品。
- [ ] 使用屏幕定位和方向反馈控制摇杆与视角，按点确认进度，不用固定时长操作推定到达，不在运行中要求玩家对准或标点。
- [ ] 原始路线的必需 teleport 尚未支持时不可整条启动；可用无 teleport 的真实地面样本，或明确标为仅导航分段验证，不将分段算作原路线通过。
- [ ] 未知位置、移动无进展、配置改变和运行条件失效时有界停止；保留主动停止、迟到回执不重启和可控输入释放。
- [ ] 贯通应用任务启动、核心决策、Android 实际输入、点位进度和结果显示，并从完整任务入口测试点位语义、重复位置、偏离与异常。
- [ ] 真机在短地面路线验证实际到点与朝向、无人游戏操作和释放；记录误差、到点阈值和各点证据，不宣称传送或采集已经通过。
