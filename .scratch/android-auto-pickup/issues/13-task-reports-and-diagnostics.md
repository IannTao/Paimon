# 13: 查看任务报告并主动开启本地诊断

<!-- paimon-github-archive -->
> 2026-10-31 已迁移到 [GitHub #14](https://github.com/IannTao/Paimon/issues/14)。本地编号 13 仅作追溯；以下为迁移前快照，当前状态、依赖及讨论以 GitHub 为准。

**What to build:** 用户查看一次采集任务的成功、失败或主动停止结果、资源点进度、恢复记录和停止原因，可主动开启诊断保存必要画面供事后复核。

**Blocked by:** [09: 从固定起点完成单资源点跑图采集闭环](09-single-resource-gathering.md)；09 的单资源点真机闭环必须有通过证据，仅关闭工单不足以解除阻塞。

**Status:** ready-for-agent

**Lifecycle:** open

**Source:** [Android 全自动跑图采集规格](../../../docs/specs/android-auto-pickup.md)。

同机独立运行，Rust 核心与 Kotlin 平台接入；仅通过屏幕观察与 Android 系统输入操作游戏，不读写游戏内存或修改游戏文件，不预设 Root 或日常外部设备控制。执行期间不依赖玩家游戏操作，遵循 ADR 0003 的全自动采集方向，不依赖旧真实触控共存门槛。测试以完整采集任务入口的外部行为为主，替身与回放不能替代真机游戏证据。

- [ ] 在已有基础结果上提供完整本地任务报告，区分执行结果与证据未验证，不将命令成功写成游戏采集成功。
- [ ] 诊断默认关闭；关闭时无截图持久化，主动开启才保存必要画面，关闭后停止新增截图。
- [ ] 记录实际保留和清理方式，不默认持续录屏、不上传、不引入日常网络依赖。
- [ ] 诊断开关不改变导航、拾取范围、启停或恢复行为；不要求运行中人工标注。
- [ ] 从真实任务验证报告与截图保存行为，断开外部控制连接后任务仍可独立运行。
