# 10: 正确处理多个拾取提示和混合交互

<!-- paimon-github-archive -->
> 2026-10-31 已迁移到 [GitHub #11](https://github.com/IannTao/Paimon/issues/11)。本地编号 10 仅作追溯；以下为迁移前快照，当前状态、依赖及讨论以 GitHub 为准。

**What to build:** 在自动采集任务到点后连续处理多个明确物品，提示变化时重新判断目标，遇到对话、宝箱、调查或未知提示不误点。

**Blocked by:** [09: 从固定起点完成单资源点跑图采集闭环](09-single-resource-gathering.md)；09 的单资源点真机闭环必须有通过证据，仅关闭工单不足以解除阻塞。

**Status:** ready-for-agent

**Lifecycle:** open

**Source:** [Android 全自动跑图采集规格](../../../docs/specs/android-auto-pickup.md)。

同机独立运行，Rust 核心与 Kotlin 平台接入；仅通过屏幕观察与 Android 系统输入操作游戏，不读写游戏内存或修改游戏文件，不预设 Root 或日常外部设备控制。执行期间不依赖玩家游戏操作，遵循 ADR 0003 的全自动采集方向，不依赖旧真实触控共存门槛。测试以完整采集任务入口的外部行为为主，替身与回放不能替代真机游戏证据。

- [ ] 对首版明确识别的直接拾取物品全部处理，不新增黑白名单；每次操作后依据当前画面选择后续目标。
- [ ] 提示消失、移动或重排后不沿用失效坐标，不重复计算同一次取得结果。
- [ ] 混合出现对话、宝箱、调查和模糊提示时只处理明确拾取提示，不执行攻击或采矿。
- [ ] 从采集任务入口验证多个提示、重排、混合交互及全部处理后的结果；在真实游戏记录无人操作与误触情况。
- [ ] 未确认物品结果不得计为成功，保留停止和释放输入行为。
