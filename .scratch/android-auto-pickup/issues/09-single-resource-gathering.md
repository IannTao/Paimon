# 09: 从固定起点完成单资源点跑图采集闭环

> 2026-10-31 已迁移到 [GitHub #10](https://github.com/IannTao/Paimon/issues/10)。本地编号 09 仅作追溯；以下为迁移前快照，当前状态、依赖及讨论以 GitHub 为准。

**What to build:** 选择一条已导入并通过整条预检的 BetterGI 基础路线后一次启动，程序自动定位、完成路线要求的传送与按点移动，到达资源点后调整视角、拾取并确认结果，全程无需玩家操作。

**Blocked by:** [08: 自动调整视角并拾取近处单个物品](08-camera-and-nearby-pickup.md)

**Status:** ready-for-agent

**Lifecycle:** open

**Source:** [Android 全自动跑图采集规格](../../../docs/specs/android-auto-pickup.md)。

同机独立运行，Rust 核心与 Kotlin 平台接入；仅通过屏幕观察与 Android 系统输入操作游戏，不读写游戏内存或修改游戏文件，不预设 Root 或日常外部设备控制。执行期间不依赖玩家游戏操作，遵循 ADR 0003 的全自动采集方向，不依赖旧真实触控共存门槛。测试以完整采集任务入口的外部行为为主，替身与回放不能替代真机游戏证据。

- [ ] 使用固定上游提交的真实基础路线作为首条完整任务，优先选择已核查的 7 点琉璃百合样本；沿用原文件、点序与语义，不删除 teleport 或其他必需点，记录定位/到点判据和实际拾取证据。
- [ ] 启动前检查整条路线能力和当前画面；需要传送时由程序完成并重新定位，不满足条件则报告原因且不盲目移动，不要求玩家补做。
- [ ] 移动根据连续屏幕反馈修正；偏离或进度无法确认时有界停止，不把固定时长操作视为到达。
- [ ] 真机贯通到点、对准、取得物品、结束和释放输入，作为新方案首个完整技术门槛；缺少真机证据不得判为通过。
- [ ] 回放场景覆盖正常采集、错误起点、移动无进展和取得物品未确认；从任务入口验证结果，不固定内部调用顺序。
- [ ] 记录本路线的重复验证方案与后续验收阈值提案；未确认的数值不写成用户承诺。
