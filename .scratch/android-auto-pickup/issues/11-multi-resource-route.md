# 11: 连续完成短路线上的多个资源点

<!-- paimon-github-archive -->
> 2026-10-31 已迁移到 [GitHub #12](https://github.com/IannTao/Paimon/issues/12)。本地编号 11 仅作追溯；以下为迁移前快照，当前状态、依赖及讨论以 GitHub 为准。

**What to build:** 一次启动后，程序依次到达短路线上多个资源点，各自拾取并确认后自动推进，完成全部资源点后结束，无需逐点确认。

**Blocked by:** [09: 从固定起点完成单资源点跑图采集闭环](09-single-resource-gathering.md)；09 的单资源点真机闭环必须有通过证据，仅关闭工单不足以解除阻塞。

**Status:** ready-for-agent

**Lifecycle:** open

**Source:** [Android 全自动跑图采集规格](../../../docs/specs/android-auto-pickup.md)。

同机独立运行，Rust 核心与 Kotlin 平台接入；仅通过屏幕观察与 Android 系统输入操作游戏，不读写游戏内存或修改游戏文件，不预设 Root 或日常外部设备控制。执行期间不依赖玩家游戏操作，遵循 ADR 0003 的全自动采集方向，不依赖旧真实触控共存门槛。测试以完整采集任务入口的外部行为为主，替身与回放不能替代真机游戏证据。

- [ ] 先使用每点单个明确物品的窄路线，使用导入路线的原始顺序贯通资源点间导航、传送要求、进度展示和最终结果，不要求任意路线编辑器，也不由玩家逐点补操作。
- [ ] 只有当前资源点取得结果有证据才计为成功并推进；资源缺失或结果无法确认时明确停止和报告，不默认为成功。
- [ ] 不重复处理已完成资源点；最终完成、主动停止和运行条件中断均释放输入。
- [ ] 通过完整任务行为验证至少两个资源点的推进、第二点异常和最终结果；真机执行全程无人游戏操作。
