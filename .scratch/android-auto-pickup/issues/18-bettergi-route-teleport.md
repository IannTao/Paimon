# 18: 自动完成导入路线要求的传送并重新定位

<!-- paimon-github-archive -->
> 2026-10-31 已迁移到 [GitHub #19](https://github.com/IannTao/Paimon/issues/19)。本地编号 18 仅作追溯；以下为迁移前快照，当前状态、依赖及讨论以 GitHub 为准。

**What to build:** 程序识别导入路线的 teleport 要求，通过手机游戏地图完成传送，确认返回游戏且位置匹配，再交给后续路径点执行，全程无需玩家补操作。

**Blocked by:** [16: 将手机屏幕定位对应到 BetterGI 游戏坐标](16-bettergi-game-coordinate-localization.md)，且基础场景坐标定位须有真机通过证据；不依赖 17 的地面导航实现。

**Status:** ready-for-agent

**Lifecycle:** open

**Source:** [全自动跑图采集规格](../../../docs/specs/android-auto-pickup.md)、[路径点兼容方案](../../../docs/bettergi-pathing-compatibility.md)。

遵循 ADR 0002、0003、0004：同机独立、本地处理、屏幕观察加系统输入，执行期间无人游戏操作。导入、定位和执行的通过证据分别记录，不以旧触控共存门槛阻塞，也不以 07 已通过替代本票能力验证。

- [ ] 从导入路线读取地图与传送点游戏坐标，自动打开地图、识别目标、执行传送并观察结果；不把传送坐标直接当作屏幕点击像素。
- [ ] 明确地图层级、可用传送点、起始画面和本阶段支持条件；未知地图、未解锁/不可用目标或未支持动作在执行前或确认失败时明确停止，不猜测点击。
- [ ] 用真实画面证明加载结束、返回可游玩状态并重新定位到目标附近；命令成功或加载动画消失不能单独作为传送成功。
- [ ] 保留原 teleport 点、action 及参数语义；基础空动作传送可先支持，force_tp 或其他未支持行为必须报告，不能悄悄删掉首点或让玩家手动传送。
- [ ] 整次传送有期限和有限恢复，锁屏、切离游戏、权限或画面失效及主动停止时结束并释放可控输入，不在其他应用继续点地图。
- [ ] 从导入任务入口验证基础琉璃百合路线首个传送点、传送失败与中断，真机确认实际位置和无人操作；按能力矩阵仅解锁已验证部分。
