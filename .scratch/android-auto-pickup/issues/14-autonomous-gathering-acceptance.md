# 14: 整合短路线真机验收并交付自用 APK

<!-- paimon-github-archive -->
> 2026-10-31 已迁移到 [GitHub #15](https://github.com/IannTao/Paimon/issues/15)。本地编号 14 仅作追溯；以下为迁移前快照，当前状态、依赖及讨论以 GitHub 为准。

**What to build:** 交付能独立完成短路线全自动跑图采集的 APK、运行准备说明和可复核验收记录，覆盖连续资源点、混合提示、有限恢复及诊断。

**Blocked by:** [10: 正确处理多个拾取提示和混合交互](10-mixed-and-multiple-prompts.md)、[11: 连续完成短路线上的多个资源点](11-multi-resource-route.md)、[12: 采集受阻时自动有限恢复并明确结束](12-bounded-autonomous-recovery.md)、[13: 查看任务报告并主动开启本地诊断](13-task-reports-and-diagnostics.md)；各阻塞工单要求的真机验证证据须有效，仅关闭工单不足以替代通过证据。

**Status:** ready-for-agent

**Lifecycle:** open

**Source:** [Android 全自动跑图采集规格](../../../docs/specs/android-auto-pickup.md)。

同机独立运行，Rust 核心与 Kotlin 平台接入；仅通过屏幕观察与 Android 系统输入操作游戏，不读写游戏内存或修改游戏文件，不预设 Root 或日常外部设备控制。执行期间不依赖玩家游戏操作，遵循 ADR 0003 的全自动采集方向，不依赖旧真实触控共存门槛。测试以完整采集任务入口的外部行为为主，替身与回放不能替代真机游戏证据。

- [ ] 开始最终验收前，落实并记录固定路线、起点、成功证据、重复次数、成功率和时间及性能指标；未确认的业务阈值明确列为待确认，不能自行写成已获接受。
- [ ] 在基准设备固定游戏设置下重复完整任务；成功任务玩家游戏操作为 0 次，人工补操作计失败，误点范围外交互目标为 0 次。
- [ ] 整合验证多资源点上的多提示拾取、资源缺失、有界恢复、权限或画面中断、切离游戏、锁屏与主动停止；全部结束路径释放输入。
- [ ] 默认空闲、授权准备、显式启动、停止入口、本地报告与诊断构成可使用的完整流程，日常不依赖电脑、其他设备或网络。
- [ ] 记录成功率、完成时长、帧率、温度和功耗；失败与未验证明确列出，不沿用旧手动游玩验收数值作为新门槛。
- [ ] 交付可安装 APK、版本信息、起点与显示配置说明、复现步骤及证据；不将历史触控共存测试计为新方案已通过。
